# OpsAssistant Roadmap

One product, built in twelve milestones. Written to be *done*, not just read.

| File | What it covers |
|---|---|
| [00-what-you-are-building.md](00-what-you-are-building.md) | The project in plain language: the problem, an example request/response, who uses it, and how it grows |
| [milestone-01-domain-and-parsing.md](milestone-01-domain-and-parsing.md) | Domain model, streaming log parsers, deterministic rules, CLI. No AI, no DB, no API. |
| [02-discovery-with-operations.md](02-discovery-with-operations.md) | Questions for the operations team, known shared-hosting pain points, and an email you can send |
| *milestone-02 …* | Written on completion of the previous milestone's checklist |

Each milestone has the same nine sections: topics to learn (and why), learning depth, hands-on exercises, project implementation, expected project state, testing, deliberate failure scenarios, skills gained, and a completion checklist.

**Rule:** a milestone is finished when the checklist is honestly green — not when the code runs.

`../production_ai_engineer_project_roadmap.md` is a dense end-to-end reference for the same product; use it to look ahead at the final architecture, evaluation strategy, and Azure design.
